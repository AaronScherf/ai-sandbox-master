# Optional Antigravity synthesis for video lecture notes: brainstorm

Status: proposal for Claude to review, not a design decision or an implemented driver. Scope is the language-model synthesis of already transcribed YouTube lectures. Slide screenshots are a separate question in TODO-0071. Related tracker items: TODO-0072 (this pipeline), TODO-0023 and TODO-0007 (subscription mode for other pipelines).

## Goal and current boundary

Let the user choose, per video-note run, between the existing local Ollama synthesizer and an attended Antigravity Gemini agent using the user's subscription. Keep the existing playlist discovery, audio download, CPU Whisper transcription, grouping, note format, and Source Indexer integration unless a specific dependency forces a change. The option should make it clear which work still uses Ollama or the Gemini API. Do not treat the Antigravity subscription as a Python API key.

The current path is `pipeline.py`: fetch metadata -> download audio -> transcribe/cache timestamped segments -> `embed_transcripts()` and `group_videos()` -> `build_synthesis_prompt()` -> `synthesize_group_note()` -> write Markdown and `.meta.json` -> index the note. The CLI has no synthesis-driver option. `synthesize_group_note()` calls local Ollama with `qwen2.5:7b-instruct` by default; `embed_transcripts()` separately calls local Ollama's `nomic-embed-text` for every transcript. The indexer uses a Gemini API client for classification and an embedding. Existing group state only hashes video membership and transcript text, so a different synthesis driver or prompt alone does not trigger regeneration. These are code observations, not a live test of an Antigravity path.

Existing patterns to compare:

- `agent/tutor/README.md` and `agent/tutor/bootstrap_prompt.md`: an IDE agent follows a generated CLI contract; local code owns state, validation, and output. Tutor runtime makes no model API call, though prep uses a query embedding.
- `pipelines/transcribe_notes/agent_driver.py`, `agent_work.py`, and `agent_submit.py`: implemented `--driver agent --collect` / `--submit` task-card handoff. The agent fills cards, and submit validates and resumes work. This is the closest transport precedent, but its page validator and cache semantics cannot simply be reused for lecture synthesis.
- `agent/study_guide/cli.py` and `agent/study_guide/revise/run.py`: current draft, enhance, and revise model work uses the metered Gemini API. Subscription mode is tracked in TODO-0007/TODO-0023; it has not established a reusable Antigravity LLM client for Python.
- `docs/status/generate_video_notes/2026-09-06-video-lecture-notes-status.md`: small live audio-to-note runs succeeded, but the full playlist path was not validated live. A corrected large 3-video Ollama prompt did not finish within 20 minutes on CPU, and a single-video retry still failed to provide useful per-concept timestamp citations. Antigravity output quality and speed for this workload are untested.

## Candidate flow for review

1. The user selects `ollama` or `agent` explicitly. Preserve the current Ollama behavior as one option. For agent mode, prepare transcript group tasks instead of calling `synthesize_group_note()` or writing a note immediately.
2. Each task contains the ordered member video IDs, source URLs/titles, bounded timestamped transcript text, the synthesis instructions, an expected output path and format, and a fingerprint of all inputs that affect the result. A local worklist tells the IDE agent what is pending. The agent writes the response to the task artifact using its own Antigravity session; Python does not impersonate an Antigravity API.
3. A separate submit command validates the exact task identity and output before publishing. At minimum, parse the output, reject empty/truncated notes, verify that citation URLs and timestamps refer to the supplied segments, and check coverage across member videos. Structural checks cannot prove the mathematical summary is correct, so compare a small real sample with transcripts before relying on the mode. If human acceptance of a draft becomes part of the workflow, use the project's interactive Artifact decision surface.
4. Only after successful validation, write the Markdown and sidecar to `academic_notes/<course>/lecture_notes/` and run the existing indexer. Record driver, prompt version, source fingerprint, and validation result in machine state/provenance. Failed or unfinished tasks remain pending; a retry must not publish a partial note or make duplicate indexing calls.

This is a candidate shape, not a settled CLI, storage layout, review policy, or grouping change. The smallest useful release is an attended, one-group agent handoff that resumes safely and produces the same note/sidecar as the Ollama path. A service, scheduler, or generic cross-pipeline agent framework is unnecessary for that first release. When nobody is present in Antigravity, agent tasks wait; there is no unattended execution mechanism in the current code.

| Stage | Discovery and scope | Side effects and cost | Output, repeatability, verification |
| --- | --- | --- | --- |
| Existing YouTube + Whisper path | Explicit URLs or playlist; one audio transcript per video | YouTube network transfer, local CPU/disk; no synthesis API call | Timestamped JSON transcript cached by video ID; already exercised on small live batches |
| Existing grouping | Course's transcribed videos; playlist/title rules and transcript embeddings | Local Ollama embedding call per transcript, even when a later rule may not need clustering | Groups in memory; prior small live batches exposed questionable cluster membership |
| Existing Ollama synthesis | One prompt per group | Local model compute; very large group prompts can be slow | Markdown note; membership/transcript hash skips unchanged groups, but does not include driver or prompt |
| Proposed Antigravity synthesis | Explicit selected group tasks derived from the same transcripts | Attended IDE-agent use under subscription limits; no direct Python model call; local handoff files | Agent-filled artifact -> deterministic checks -> note; fingerprint and status needed for safe resume; live quality unverified |
| Existing indexing | Each newly written group note | Gemini API classification plus embedding, with project quota/billing | Index card; retain its current API credential and verify registration after submit |

Repository boundaries matter. Code and the current ignored `.cache`/`.state` are in the outer `ai-sandbox-master` repository. `academic-hub/.agent_work` (used by agent-driven note transcription) is ignored under that outer repository and is a candidate handoff location; the tracked `.index/` also belongs to the outer repository. **Published** `academic-hub/academic_notes/<course>/lecture_notes/` files belong to a separate nested `academic_notes` Git repository, which is absent from this outer worktree and syncs to a tablet through Obsidian. Confirm task-file cleanup and visibility before reuse, and give the nested notes repository its own assigned writer/worktree for any production write. Coordinate index writes and Obsidian sync separately. A production run must use explicit hub and notes paths; the default `../academic-hub` in an outer worktree is not a safe copy of the live nested vault.

## Pitfalls and questions for Claude

- **Driver changes can be skipped.** Current `member_content_hash` ignores the synthesis driver, model, and prompt. If an Ollama note already exists, an agent run with unchanged transcripts is counted as unchanged. Define a synthesis fingerprint and migration rule before adding the selector. Current `group_id` values are ordinal (`g_0001`, etc.), so task identity should be derived from member IDs and content rather than that counter alone.
- **One large group may exceed a practical agent task.** The playlist default can merge a whole lecture series; the previous 3-video prompt was about 22,000 tokens. Decide whether to bound tasks per video or segment and combine partial summaries, how to preserve cross-video coverage, and whether the final combine step gets enough context. Do not assume Antigravity's effective context or quota equals the Gemini API's.
- **Citations can look plausible while being wrong.** The present prompt requests timestamp links, but the recorded Ollama output did not satisfy it. An agent may invent a URL or attach a real timestamp to an unsupported claim. Validate link syntax and membership automatically, then use source-grounded sampling for semantic correctness and slide-specific claims if visual input is added later.
- **A pending agent result is not an API failure.** Separate `pending`, `filled`, `accepted`, `bounced`, and `published` states. Avoid the current pipeline's immediate write/index path and avoid generic retry/fallback logic accidentally invoking Ollama when agent work is merely waiting. Define what happens after a crash between note write and index registration.
- **Shared destination and atomicity matter.** Current `write_group_note()` writes Markdown and sidecar directly, then indexes. A submit path should prevent partial publication on interruption and audit the final note, sidecar, state, and index for the exact group. Coordinate with any other writer or vault sync touching those paths.
- **Subscription savings are limited and variable.** Agent synthesis can avoid Ollama CPU time and a synthesis API charge (there is none today), but may consume Antigravity quota and human/agent time. Local Ollama embeddings still run, and Gemini API classification/embedding still has separate limits and billing. Decide whether the goal is better note quality, faster large-group completion, removing Ollama entirely, or lower cash spend; each changes the scope. Check current Antigravity terms and limits when implementing.
- **The existing study-guide code is not proof of this mode.** It uses `GeminiClient` with an API key for generation. The tutor demonstrates attended agent control, and note transcription demonstrates a file handoff, but neither verifies video-note synthesis quality or a Python-callable subscription endpoint.

Claude should settle the first release's task granularity, acceptance policy, state/fingerprint schema, destination for ignored task files, and whether grouping embeddings remain local Ollama. Then validate one short single-video task and one multi-video task against the existing note contract before changing the normal pipeline path. No Antigravity run or API call was made for this brainstorm.
