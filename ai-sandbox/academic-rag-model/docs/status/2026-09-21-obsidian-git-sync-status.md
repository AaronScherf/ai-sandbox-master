# Obsidian Vault ↔ Tablet Git Sync: Incident Summary and Restructuring Scope

Summary of a single session (2026-09-20/21) spent diagnosing and fixing
laptop↔tablet Obsidian sync for `ai-sandbox/academic-hub/academic_notes/`
(its own git repo, remote `academic-notes-vault` on GitHub, private —
gitignored from the main `ai-sandbox-master` repo root, same pattern as
`academic-hub/academic_resources/`). No prior doc covered this topic
directly; the closest existing references are background mentions in
`docs/status/2026-08-24-notes-transcription-status.md` and
`docs/superpowers/specs/2026-09-09-excalidraw-notes-transcription-design.md`
(both describe the original 2026-09-08/09 repo split, and both are now
slightly stale — they say "Obsidian Git plugin on both ends"; the tablet
actually uses a different plugin, **Direct Git Sync**, not `obsidian-git`).

## Sync architecture (as of this session)

- **Tablet:** Direct Git Sync plugin, configured with GitHub repo URL +
  PAT + author info + a "User defined ignore rules" text block, all
  stored in a per-device, gitignored `data.json`.
- **Laptop:** originally had no dedicated sync plugin for this nested
  vault (edits went through the *outer* `ai-sandbox-master` repo's
  `obsidian-git`, which cannot see `academic_notes/` at all since the
  outer repo gitignores that whole path). Mid-session, the user started
  opening `academic_notes/` as its own second vault on the laptop and
  using its own `obsidian-git` instance directly against the nested
  repo. `direct-git-sync` was *also* found enabled in that nested
  vault's `community-plugins.json`, unconfigured — this turned out to
  be the root cause of one incident (below).
- **Shared, tracked file:** `.gitignore` inside `academic_notes/`. Its
  header says "auto-generated by Direct Git Sync, update via plugin
  settings" — true and important: `main.js`'s `onload()` unconditionally
  calls `updateGitIgnore(this.settings.ignoredPaths)` on **every plugin
  load, on every device**, stamping the "User defined ignore rules"
  section from *that device's own local settings*, discarding whatever
  is currently in the file. The file is not a stable source of truth;
  each device's local config is. Any new ignore rule must be added to
  **every** device's plugin settings to survive the next restart
  anywhere (for a device where the plugin is vestigial, like the laptop
  post-fix, hand-editing its local `data.json` directly is safe — it's
  gitignored and never syncs).

## Incidents found and fixed this session

1. **Laptop 23 commits behind, no true divergence.** Plain `git pull`
   fix, no conflicts.
2. **Merge conflict on `.obsidian/community-plugins.json`** between a
   laptop `obsidian-git` "vault backup" commit and a tablet Direct Git
   Sync commit that had each independently changed the enabled-plugin
   list. Resolved manually.
3. **`excalidraw-stylus-menu` plugin fully localized Russian→English**
   (all user-visible strings: menu labels, notices, settings tab,
   command names — source comments left untouched, they're invisible to
   users) plus a new **Eraser** button added to the stylus insert menu,
   calling Excalidraw's real `setActiveTool({type:"eraser"})` API rather
   than a DOM `aria-label` click hack.
4. **15 PDFs (~21MB) leaked to GitHub** via a laptop `obsidian-git`
   auto-backup commit, because `direct-git-sync`'s "User defined ignore
   rules" had gone empty (see root cause above — this was the laptop's
   never-configured local copy stamping the shared file blank).
   Untracked (`git rm --cached`, files kept on disk) and rules restored.
5. **`.excalidraw.svg` auto-export files (8 files, 51MB and growing —
   "auto-export, keep updated" regenerates them on every drawing edit,
   so if ever tracked this compounds continuously, unlike a one-time
   PDF leak) added to ignore rules** before they were ever committed.
6. **`.obsidian/community-plugins.json` untracked entirely** and added
   to ignore rules — each device now keeps its own enabled-plugin list
   independently; plugin *code* (in tracked `.obsidian/plugins/*/`
   folders) still syncs regardless, only the enable/disable toggle
   became per-device.
7. **Root cause of tablet crash ("stages, fetches, then app minimizes")
   found: `.git` history bloat, not just current-tree leaks.**
   `git rev-list --objects --all` found **87 PDF/docx blobs, 184MB+7.5MB,
   baked into history** going back through most of the repo's life —
   `git rm --cached` only affects the current snapshot, so a fresh
   clone/fetch was still pulling the full historical weight regardless.
   Fixed with `git-filter-repo --invert-paths --path-glob '*.pdf'
   --path-glob '*.doc' --path-glob '*.docx' --path-glob '*.pptx'` on a
   scratch clone, force-pushed (`.git`: 217MB → 35MB on GitHub, 27MB
   locally after `gc --prune=now --aggressive`).
8. **Near-miss: `git reset --hard origin/main`, used to sync the real
   laptop working copy to the rewritten history, deleted 74 files
   (71 PDF + 3 docx, ~58MB of live course material — TA notes, problem
   sets, past exams, syllabi) from local disk**, since `reset --hard`
   removes any file tracked in the old HEAD but absent from the new
   target tree — this is a real difference from `git rm --cached`, which
   the user had been told (correctly, for the *earlier* incidents) left
   files on disk. Not flagged in advance; found when the user asked
   directly. Fully recovered: the pre-rewrite commit was still fetchable
   from GitHub by SHA via the API even though unreachable from any ref,
   so each missing file's original blob was pulled back via
   `gh api repos/.../git/blobs/{sha}` and written to its original path.
   **Verified two ways:** (a) `git hash-object` on all 74 recovered
   files matches their original blob SHAs exactly, (b) a full sweep of
   all 201 files tracked at the pre-rewrite commit against current disk
   state and content found 0 missing, 0 actually-different (one
   apparent mismatch was a Windows CRLF/LF `hash-object` normalization
   artifact, confirmed identical via raw byte diff against the GitHub
   blob).

## Still open as of session end

- **Tablet was still failing to fetch even after the history rewrite**
  (same "stages, fetches, minimizes" symptom). The user was setting up
  a fresh vault on the tablet to do a clean clone rather than deleting
  `.git` in place, as a workaround/diagnostic. Outcome not yet known —
  check back here or ask before assuming the tablet is fixed.
- **Ignore rules may still be incomplete on the tablet's own local
  Direct Git Sync settings** (`*.excalidraw.svg`,
  `.obsidian/community-plugins.json` were added to the laptop's copy
  and to the shared `.gitignore`, but the user's confirmation that the
  tablet-side plugin settings were updated to match is unconfirmed as
  of this doc).
- **Fragility of the whole ignore-rule mechanism**, given how many times
  it silently broke in one session, is the direct motivation for the
  restructuring scoped below.

## Restructuring problem scope (for brainstorming — not decided yet)

**The ask:** move PDFs (and likely the auto-exported SVGs) currently
living *inside* `academic_notes/` (under `math-camp/`, `econometrics/`,
`microecon/`, etc. — the tablet-synced repo) out to
`academic-hub/academic_resources/` (tracked in the *outer*
`ai-sandbox-master` repo, already 1.1GB, already has an established
pattern of selectively gitignoring its heaviest subpaths — see
`ai-sandbox-master/.gitignore` lines ~35 and ~142 — and structurally
never touched by tablet sync at all). Motivation: today's incidents were
only possible because heavy source files and lightweight processed
notes live in the *same* repo, making protection entirely dependent on
the ignore-rule mechanism shown above to be fragile across two
independently-configured devices. Moving heavy files out removes the
dependency entirely for anything relocated, rather than continuing to
patch the ignore rules.

**Known complexity, not yet scoped in detail:** the user confirmed "a
lot of filepaths and scripts would need updating." A first-pass grep
during this session found **19 files in `academic-rag-model`** that
reference `academic_notes/` paths combined with raw-material folder
names (`math-camp`, `professor_notes`, `ta_notes`, `handwritten_notes`,
`problem_sets`) or `academic_resources`, including both pipeline code
and its tests:

- `indexer/index_search.py`, `indexer/duplicate_check.py`,
  `indexer/index_card.py`
- `audio_generator/pipeline.py`, `audio_generator/discovery.py`
- `postprocessing/postprocess_notes.py`
- plus the corresponding files under `tests/`

This list is a starting point from a path-pattern grep, not a vetted
inventory — the brainstorming pass should confirm scope, not assume
this list is complete or that every match needs a code change.

**Desired end state (per the user, not yet designed):** raw/heavy
source files (PDFs, SVGs, and similar) live under `academic_resources/`;
processed outputs (converted markdown, `.excalidraw.md` notes) continue
to live under `academic_notes/` so they keep syncing to the tablet.
Also in scope per the user: updating relevant README files and the
git-ignore-rule setup (`.gitignore` contents, Direct Git Sync's
per-device "User defined ignore rules") to match the new split, so
today's fragility doesn't just relocate to a new pair of folders.
