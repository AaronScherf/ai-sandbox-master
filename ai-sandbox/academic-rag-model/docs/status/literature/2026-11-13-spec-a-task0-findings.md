# Spec A Task 0: preconditions findings (2026-11-13)

Plan: `docs/superpowers/plans/2026-11-13-spec-a-indexing-classification-applicability.md`. Evidence from the worktree `claude/spec-a-research-profile` (base 13546ce6) and the main checkout's untracked `research/` data.

1. **Identity survives a move: yes.** `compute_file_id` (`core/indexer/index_card.py:66`) is a truncated SHA-256 of the PDF bytes, so it does not depend on the path. `move_card` (`:524`) changes `course`, `path`, `source_pdf_path`, `source_asset_path` only and keeps `file_id`. Journal-article cards carry no `hub_id` (0 of 62 tracked research cards); `file_id` is the join key for this work. No new identity needed.
2. **Card extension point.** Cards are JSON shards per course (`research/.index/<folder>.json`), read/written by `load_shard`/`save_shard`; `set_card_fields` (`:707`) is the pattern (merge into one card, no other key touched). A nested `research_profile` key is safe: `reconcile_and_write` rebuilds a card only when the content hash changes (it carries existing keys forward otherwise); the content hash is computed from the transcript `.md`, not the card. Course-material shards are never written by the new code.
3. **Frontmatter.** Journal transcripts carry YAML frontmatter (`source_pdf`, `folder_category`, `total_pages`, `routing`, `model`, `tags`). `compute_content_hash` ignores only `LOCATION_FIELDS` and `hub_id`, so writing any other key into the frontmatter would change the hash and stale the card. **Ruling: no frontmatter mirror in this release;** the profile lives on the card (the "index"). A mirror would need an allow-list in the hash first.
4. **Readers of `doc_type == "journal_article"`:** `agent/literature/papers.py:30` (`eligible_papers`) and `agent/literature/backfill_years.py:28`. Folder paths: `discovery/discover_journal_articles/topic_routing.py`, `topic_proposals.py`, and the study records. The folder move (Task 8) must go through `move_card` and then re-key these; `papers.py` reads `card["path"]` from the shard, so it follows the move.
5. **Unlanded branches.** `git diff main...<branch> --stat -- agent/literature/schema.py core/indexer/index_card.py` is empty for `codex/refine-v4`, `codex/refine-v4-trial-audit` and `claude/literature-reextract-v4`; `codex/term-selection` is not a resolvable local branch (detached worktree). No overlap found.
6. **Vocabulary.** `Vocabulary` (`agent/literature/vocab.py`) holds `Term(id, label, parent, definition, aliases)`, so tree helpers are straightforward. The committed lists in `vocab_data/` are data_source, hazard_type, population, study_design. The 3ie intervention/outcome/sector vocabularies are in the git-ignored `research/resources/3ie/vocab/`; `load_vocabularies(path)` overlays them. The tagging code must therefore take the 3ie vocab directory as a parameter (default: the main checkout's `ai-sandbox/research/resources/3ie/vocab`).
7. **Data in a worktree.** `research/.index` card shards and `.meta.json` sidecars are tracked (62 cards, 43 `journal_article`), but PDFs and transcripts are untracked. Real-corpus runs (Task 11) must point `--index-root` at the main checkout's `ai-sandbox/research`; unit tests use temporary roots.
