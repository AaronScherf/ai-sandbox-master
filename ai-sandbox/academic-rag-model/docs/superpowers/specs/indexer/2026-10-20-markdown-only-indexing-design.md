# Markdown-only academic notes: indexing design

**Status:** proposed for review; no implementation or live indexing completed.
**Scope:** `core/indexer/` and the `academic-hub` corpus, across all courses under `academic_notes/`.

## Problem and requirements

`index_search.rebuild()` discovers PDF-backed notes and several specialized outputs, but it does not discover ordinary Markdown files with no recorded upstream asset. This blocks file search, passage search, and consumers of index cards, including study-guide and problem-corpus workflows. The existing [TODO-0006](../../../trackers/academic_hub_to_do.md) names homework hints, guided solutions, and tutoring notes; econometrics `problem_set_1.md` and `problem_set_2.md` are further examples.

Index useful Markdown-only notes throughout `academic_notes/`, including nested directories and `processed_outputs/`, without duplicating PDF-backed or specialized cards. Give substantive generated sidecars and auxiliary documents their own cards when they add separately retrievable content, and link them to a known parent as companions. Record the **known provenance**: a confirmed generated document is distinct from a Markdown file whose origin is unknown. Absence of an upstream file is not proof that a note is derivative: directly authored Markdown may be primary. Keep `doc_type` about content, not provenance. Preserve current PDF, textbook, video-note, and Excalidraw behavior and existing cards. Do not rewrite notes or require a PDF. Make the new cards available to all existing index consumers, not just `problem_corpus`.

## Verified repository behavior and evidence

- `core/indexer/index_search.py` currently walks PDFs recursively and pairs each with its output Markdown; it separately discovers textbooks, video notes, and Excalidraw transcripts. Its final orphan pass depends on every live card ID being added to `seen_file_ids`.
- `core/indexer/index_card.py` hashes upstream file bytes for ordinary card IDs, but `compute_id_from_parts()` already creates derived IDs. Cards have `source_pdf_path` (a legacy name also used for non-PDF sidecars), `source_asset_path`, and `content_hash`. `generate_index_card()` makes one generation and one embedding request per card; chunking makes additional embedding requests.
- `search()` accepts an embedded orphaned card because an absent PDF does not imply absent Markdown. `chunk()` skips orphaned cards and checks file existence and content hash. New Markdown-only missing-path cards need a distinct search rule.
- A read-only inventory in the main checkout found 647 Markdown paths and 387 paths without a matching card path; **387 is not an eligible count**. A varied sample included genuine problem sets and homework hints, but also raw `*.excalidraw.md`, generated `.rag.md`, `.excalidraw.questions.md`, textbook chapter `.rag.md` files, and manifests. About 253 unmatched paths were below `processed_outputs/`, so excluding that directory wholesale would miss useful notes. Candidate classification must be validated against a varied live sample before aggregate counts are trusted.
- Excalidraw `*.excalidraw.questions.md` is already a separate `excalidraw_questions` card derived from its parent note ID. By contrast, `rag_md_path` makes a `.rag.md` an alternate rendering of the **same** indexed file, so indexing that rendering again as another file would duplicate it. Chapter-level textbook `.rag.md` files are different: a chapter can be a substantive child of a whole-book card. These categories cannot be decided by suffix alone.
- `academic_notes/` is a nested Git repository; `academic-hub` code and `.index/` are in the outer repository. The new scanner only reads the nested repository. Existing `rebuild` and `chunk` mutations hold the shared corpus lock, but other index writers have not all adopted it (`core/indexer/README.md`).

## Capability map

| Capability | Current | Proposed release |

| Scope | `rebuild --course`; no exact Markdown repair target | Course or exact hub-relative Markdown path; default rebuild includes eligible Markdown-only files |

## Candidate discovery and ownership

Walk `academic_notes/<course>/` recursively in deterministic path order. Skip hidden directories, empty files, and files outside that tree. Do **not** skip all of `processed_outputs/`: the econometrics Markdown problem sets live there. Classify every path before any paid call:

1. Build an ownership map from existing card `path` and `rag_md_path`, plus paths the current PDF, textbook, video-note, and Excalidraw discovery passes claim even when no card exists yet. A PDF-paired Markdown path remains owned by the PDF pass, including mirrored `academic_resources/` sources. The existing Excalidraw question producer remains owner of its already-separate question card; this pass must not mint a duplicate.
2. Classify a path as an **attached rendering** when a parent card's `rag_md_path` points to it, or when producer metadata explicitly makes it the alternate representation of that one parent. Keep it retrievable through the parent card, but do not create a second card. Raw Excalidraw canvas Markdown and audio/video `__index.md` machine manifests are not standalone content cards. Do not use a blanket `.rag.md` or `processed_outputs/` exclusion.
3. Classify a substantive generated child as a **separate companion** when producer metadata or a documented deterministic producer path gives one unique parent and a distinct content role. Examples to verify include textbook chapter files versus the whole-book card, generated question sidecars, and generated solution/hint documents. Add or retain a child card with its own embedding/chunks and a link to the parent. A chapter whose only available text is an already-attached whole-book rendering must not create a second card for the identical span merely from a filename match.
4. Index useful auxiliary documents with no verified producer relationship as Markdown of **unknown origin**, even if a name suggests `solution` or `hint`. Link to a parent only when an explicit pointer or unique, documented structural match establishes the relationship; a filename role token alone does not prove generation or parentage. Report `unlinked_auxiliary` or `ambiguous_parent` in preview, but do not discard the content. If two producers claim a path, report `ambiguous_owner` and leave it unindexed until classification is corrected.

The classifier returns a reason, intended owner, origin evidence, parent ID/path when known, and `index_separately` for every scanned path, including exclusions. Existing Markdown-only and companion cards must count as seen on repeated rebuilds. Matching uses normalized hub-relative paths and checks case collisions on Windows. A path cannot be indexed twice under two producers. Missing or corrupt files yield per-target errors rather than aborting unrelated targets.

| Example | Classification | Card behavior |
| --- | --- | --- |
| Econometrics Markdown problem set with no recorded source | Unknown-origin Markdown | Own card; no invented parent |
| Hint or solution note with no producer evidence | Unknown-origin auxiliary | Own card; link only if a unique documented parent match exists |
| Excalidraw question sidecar | Confirmed generated companion | Existing separate card; backfill parent and origin metadata |
| Distinct textbook chapter generated from a book | Confirmed generated companion | Own card and chunks linked to book card |
| `.rag.md` named by a parent card's `rag_md_path` | Attached alternate rendering | No second card; parent search uses rendering |
| `__index.md` machine manifest | Non-content auxiliary | No content card; preview explains exclusion |

## Card schema and identity

New unknown-origin notes use `source_kind: "markdown_only"`; confirmed generated children use `source_kind: "generated_companion"`. Both have `source_pdf_path: null` and `source_asset_path: null` unless an existing specialized producer already records a real source path. `path` points to the child's own Markdown. A linked child also has `companion_of_file_id`, `companion_role` (for example `chapter`, `questions`, `solutions`, `hints`), and `relationship_basis` (producer metadata or the named deterministic matching rule). These relationship fields do not imply generation: an unknown-origin note can have a verified companion link while retaining `source_kind: "markdown_only"`. Never set `generated_companion` from a filename guess alone. `doc_type` remains the content classification. Legacy cards with no `source_kind` retain their current meaning unless their specialized producer verifies and backfills it. The Excalidraw question producer must backfill `source_kind: "generated_companion"` and its parent/role/basis fields on its existing cards without reminting their IDs. Adapt card creation, failure cards, reconciliation, and readers so null upstream paths are valid. Audit callers that call `.replace()` or open `source_pdf_path` unconditionally. `page_count` is null for new Markdown cards.

Derive a namespaced ID from `compute_id_from_parts([source_kind, normalized_hub_relative_path])` **only for a new file with no existing card at that path**. This keeps edits at the same path on one card; `content_hash` invalidates its summary, embedding, and chunks when text changes. If later producer evidence changes `source_kind` from unknown-origin to generated companion, update that card's provenance and parent fields in place; do not mint a second ID merely because the classification improved. For a move or rename, reuse an old card ID only when its old path is absent and there is exactly one unmatched old card with the same content hash and compatible ownership; patch path/course without paid regeneration. If zero or multiple cards match, create a new path ID and mark the old missing card orphaned; report the ambiguity. An edit and move in the same interval cannot be identified without more state and follows this latter rule. Never merge two simultaneously present copies solely because they have equal bytes. For a companion, resolve `companion_of_file_id` afresh from the producer/parent path on rebuild; if the parent ID changes, rebind the child without reminting its own ID. A missing parent leaves the existing child searchable if its own text remains present, but preview reports the dangling relationship.

An active Markdown-only or generated-companion card whose **own Markdown file** disappears becomes `orphaned: true` on rebuild and is omitted from file search and passage search until the file reappears or is reconciled. A missing parent alone must not orphan a present companion, including an existing Excalidraw question sidecar. This exception is limited to these two source kinds; PDF-backed orphan search semantics stay intact. `--prune` may delete a missing child card under existing policy. On reappearance, clear `orphaned`. A changed file is reindexed on rebuild under its stable ID; the chunk pass then replaces stale chunks based on `content_hash`. Search may return parent and substantive companion as distinct results; an attached rendering remains represented by its parent only.

## Commands and safe application

Add a read-only Markdown preview and exact-target apply interface to `index_search` (for example, `index-md --course COURSE [--file HUB_RELATIVE_MD] --dry-run --json`, then the same selector without `--dry-run`). `--file` must resolve to exactly one path beneath the selected course and reject traversal, symlink escapes, and ambiguous matches. JSON results contain one row per candidate with path, owner/classification reason, `source_kind`, `index_separately`, parent ID/path/role/basis when known, intended file ID, prior card ID, content hash, action (`new`, `refresh`, `move`, `attach`, `unchanged`, `skip`, `error`), estimated paid calls, and final status. The exact-target path must not run the corpus-wide orphan pass. A course/batch preview reports totals before a live run and supports a configured maximum number of paid card operations; exceeding it exits before writes or calls.

Ordinary `rebuild` includes eligible unknown-origin Markdown and generated companions by default and adds their IDs to the shared seen set before orphan handling. Its course filter remains effective. A preflight applies a default cap of 25 new/changed cards in these two classes per invocation; a larger set fails before any writes or paid calls and reports the required cap and candidate list. `--max-markdown-paid N` can deliberately raise that limit after preview. The cap does not change existing producer budgets. Make each card/shard write atomic or use the existing atomic shard writer if verified, and hold the corpus lock for mutation. Coordinate with other writers to `.index/` during a live batch. Do not write to `academic_notes/`; no new review interface is needed because classification is deterministic and ambiguous items are skipped. Keep raw JSON as machine state, not a human decision surface.

The indexer still uses its configured API for card generation and embeddings; this proposal does not change the subscription-backed problem-corpus workflow. `chunk --course` or exact `chunk --file-id` remains the separate passage-indexing step. A file card alone supports file-level search and index-card consumers but does not establish passage availability.

## Release and verification

The smallest usable release is scanner/classifier, provenance-aware card reconciliation, separate cards for confirmed substantive companions, attached-rendering handling, default rebuild inclusion, exact-target preview/apply, search handling, and documentation. It needs no server, new persistent store, or source-note rewrite. Passage chunking uses the existing command; update it only where needed for new card metadata. A later phase may infer uncertain parent/derivation links or support Markdown-only roots outside `academic_notes/`.

Fixture tests must cover nested notes, `processed_outputs/`, PDF-paired Markdown, attached renderings versus substantive chapter/question/solution companions, existing specialized sidecars, unknown-origin hints, ambiguous/missing parents, duplicate content, edits, unique and ambiguous moves, disappearance/reappearance, `--prune`, course/exact selectors, failed API calls, idempotent reruns, and unchanged legacy cards. Test that a companion is separately searchable/chunkable while an attached rendering does not duplicate its parent in search. Compare a small varied read-only preview against the underlying live files, record false positives, and fix rules before relying on totals. For an authorized live run, preview one bounded course, apply with the same selector and call cap, then audit every target's card/path/provenance/parent/status and a sample of generated summaries against source Markdown. Confirm the nested notes repo stays clean and no public destination is used.

## Boundaries and dependencies

This work does not extract problem spans or decide whether a solution note is a standalone problem. The separate problem-corpus heading-detection fix is awaiting its own landing approval. Econometrics collection can use new index cards after both changes are landed and the targeted index/chunk audit passes. The present document is a design proposal, not evidence that code, fixture tests, or a live corpus run have succeeded.
