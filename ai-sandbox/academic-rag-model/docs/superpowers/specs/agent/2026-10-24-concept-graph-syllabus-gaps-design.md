# Concept graph syllabus gap stage: design for TODO-0079

Date: 2026-10-24. Branch: `claude/todo-0079-collect-gaps-spec`. Status: owner approved; implemented on this branch.

## Goal and evidence

After an additive `seed`, run `collect gaps --hub-root H --course C` to compare *every assigned syllabus topic and reading* with textbook section headings and the current node names by graph section. One course-level card asks an agent for missing concept and optional connection proposals. `submit` validates the card and passes a schema-version-2 `ReviewFile` to `reviews.apply_proposals`. It must not call the seed writer or mark items verified. A human reviews proposed items in the existing interactive graph page.

The [second-course status](../../../status/agent/concept_graph/2026-10-21-econometrics-second-course-status.md) records 7 additive-seed concepts followed by 21 manually found gaps, including the previously empty dynamic-causal-effects topic. The [tracker](../../../trackers/academic_hub_to_do.md) asks for a separate stage. The package [README](../../../../agent/concept_graph/README.md) and `seed.py` confirm that the material catalog, syllabus cleaner, heading extraction and private card loop already exist; `reviews.py` confirms clustering, tombstones and proposal writes. No `collect gaps` stage or syllabus-reading mapper exists today. `tools/seed_card_coverage.py` audits seed coverage but does not compare assigned readings with graph nodes. The [reviewer-proposals design](2026-10-14-concept-graph-reviewer-proposals-design.md) already defines the proposal schema and review surface.

## Card and input mapping

1. Use `core.course_materials` to find current-course syllabus and textbook material. Refuse a missing syllabus, missing graph sections, or unresolved catalog flags affecting those sources; report the exact file. Clean syllabus contact details as seed does. Extract the ordered topic/subtopic lines under its Topics/reading-list section, retaining the reading text and source path. If extraction finds no assignments, fail visibly rather than issue an empty card.
2. Resolve reading abbreviations to catalog book keys with an optional `reading_aliases` mapping in `config/seed.yaml` (for econometrics, `SW: stock`, `CT: cameron`); full book keys work without aliases. Parse references such as `SW 16.2, 16.3, 16.5` and `Hansen 3.1-3.18`. Locate a textbook chapter by its **content heading number**, not its file number: the local Stock-Watson file `15_estimation_of_dynamic_causal_effects.rag.md` says chapter 16 in its heading. Show headings within each assigned section, including unnumbered subheadings. When extraction omitted an assigned section but the book's contents names it, show that title marked `contents only; section text unavailable`. Fail collection with exact references if no heading is available. Preserve the syllabus's exact reading string for the agent.
3. Show all syllabus topics in order, with their readings and resolved textbook headings. In the same card show every graph section id/title and its current node names; indicate sections with zero nodes. Keep the full node list, even if a syllabus topic appears to map to a different section: semantic alignment is the agent's judgment, not a filename heuristic. Show the graph's kinds and topics, rejected concept ids, and proposal format. No retrieval or embedding call is needed. The card and manifest stay under the existing private work directory, outside the graph repo.
4. Ask for a YAML mapping `proposals: [{name, kind, section, topic, note?, connections?}]` and optional standalone `edges` in the existing proposal shapes. An empty `proposals: []` and `edges: []` is a valid explicit finding of no gaps. Require a short syllabus reading reference in each proposal's note, within the existing 200-character limit. The agent must propose only missing in-scope concepts, use existing sections, distinguish close technical names, and avoid new sections or direct graph edits.

## Submit and state

Add `gaps` to the stage registry. Reuse `Task`, the one-card run manifest, and `drivers.submit`; add a `gaps` stage module with `make_tasks`, `validate_result`, and `apply_result`. The CLI must skip retriever creation for `gaps`, as it does for `seed`. Store a digest of the offered syllabus/heading text, reading aliases, graph vocabulary, and graph section/node/rejected identities in the manifest subject. On submit, recompute it; if inputs changed, bounce the card and require a fresh collect. This prevents a stale comparison from writing proposals after a graph or syllabus change.

Validate the entire result against `NodeProposal`/`EdgeProposal` and the allowed graph vocabulary before writes. Convert it to one `ReviewFile` with `schema_version: 2`, the submitting agent as reviewer, and `add_node`/`add_edge` decisions; call `reviews.apply_proposals` once for the whole card. Show its applied, skipped and conflict details to the submitter. The existing function clusters similar names, checks duplicates and rejected ids, and writes accepted items as `proposed` with reviewer provenance. No separate gap ledger is needed. The run's applied status prevents repeat submit; a fresh run sees the new nodes. A later human rejection writes a tombstone; a deferred proposal remains visible as proposed in the graph page rather than reappearing as a new gap.

Human acceptance/rejection uses the existing interactive viewer and `apply-review`. The agent's card is a drafting surface, not a request for the owner to hand-edit YAML or JSON. This follows the interactive-Artifact-by-default rule without adding a second decision UI.

## Capability and boundaries

| Step | Scope and cost | Output / writes | Repeat and verification |
|---|---|---|---|
| Discover | Catalog, syllabus and assigned textbook Markdown; local scan, no API | Reads academic-hub and graph config/data; catalog may refresh its private index | Source paths and unresolved readings reported; fixture tests cover mapping |
| Collect | One course card, all syllabus topics/readings/headings/nodes; no API | Private card/manifest under `H/.agent_work/concept_graph` or `--work-dir` | Deterministic content at fixed inputs; digest recorded |
| Submit | One validated result, existing proposal rules | Writes only graph `data/nodes`, `data/edges`, and existing conflict/comment files through `apply_proposals`; no commits/pushes | Stale inputs bounce; repeated run is inert; read graph back and inspect conflicts |
| Human review | Existing built graph page and `apply-review` | Owner decisions enter the graph repo through the existing review workflow | Reject tombstones prevent resurfacing; accepted items become verified |

The monorepo contains the stage code, fixtures and this spec. Academic-hub is a directory in that same Git repository and supplies course Markdown and a private catalog cache. Econometrics and microeconomics graph repositories are separate checkouts: implementation and tests must use temporary copies or fixtures, with real graph data accessed read-only for acceptance inspection. The public site repository is outside this stage. One assigned writer is required for a graph-repo submit; collect may run read-only against it.
