# Shifting bulk drafting to subscription agents (Antigravity) - findings and recommendations

Date: 2026-10-14. Status: findings from the concept-graph work; one recommendation already implemented, the rest
pending. Tracker item: TODO-0075 in `docs/trackers/academic_hub_to_do.md`.

## Context

The concept-graph pipeline (`agent/concept_graph/`) drafts with an agent over task cards: `collect` writes cards from
code (retrieval, instructions, offered passages), an agent fills each card's `## Result`, and `submit` validates in
code and applies. In this project the agent was Gemini in Antigravity (subscription), with Claude designing,
coordinating and reviewing, and a human relaying each run between them. About 190 cards went through this way in one
session (seed, fill, link, critic across 8 sections) with almost no bounces.

## Findings

**Size of the work** (latest round; tokens are roughly characters / 4):

| Run | Cards | Average per card | Total input |
|---|---|---|---|
| fill | 17 | about 3.4k tokens | about 57k |
| link | 17 | about 9.2k tokens | about 156k |
| critic | 28 | about 2.5k tokens | about 71k |
| seed | 1 | about 16k tokens | 16k |

**Cost by route** (per round of this size, about 300k input tokens):

| Route | Claude tokens | Dollars | Turnaround |
|---|---|---|---|
| Gemini in Antigravity (subscription) | about 1 to 2k per run (a short prompt, a collect, a submit report) | none beyond the subscription | slow: one human paste and one "done" per stage |
| Gemini API (metered) | same small overhead, or less if unattended | metered: roughly cents on a Flash-class model, dollars on a Pro-class one (prices not checked; verify before a large run) | fastest: no human relay, parallel |
| Claude does the cards itself | about 300k input tokens per round, plus a conversation re-read on every tool call | none, but it spends the Claude quota | no relay, but slow and quota-heavy |

- The prompt Claude writes is a small cost. The expensive part of any turn is re-reading the conversation, and that is
  the same whoever drafts.
- The saving comes from the cards being generated by code: Claude never reads or rewrites the passages.
- Quality gates sit in code (own-words guard, citation grounding, cycle checks, meta-commentary check), so the retry
  loop is cheap and does not depend on Claude's attention.
- The real overhead is the human relay: roughly twenty paste-and-report round trips in one session.

**Weaknesses seen**

1. **The critic is probably too lenient.** The drafting agent judged its own output: 154 of 155 verdicts were
   `supports`, and the single `weak` was a real catch (a functional form listed as a component of a general problem).
   A rate that high on the same model's own work calls for a spot-check, not trust.
2. **Relay confusion.** Near-identical prompt wrappers for different stages let an agent (or a person) take a link run
   for a repeat of a fill run.
3. **A shared dependency on the paid key.** The monthly spending cap blocked card collection (query embeddings) once;
   it now falls back to the free key and then local keyword search, but a move to API drafting would add the same
   exposure to the drafting itself.

## Recommendations

1. **Ready-to-paste prompts printed by `collect` (important; implemented).** `collect` now prints, and saves as
   `PROMPT.md` in the run folder, a prompt that names the stage in capitals, gives the run directory and card count,
   shows the first line of a card's instructions so an agent can confirm it has the right run, lists stage-specific
   rules, and says not to submit. This removes the per-run prompt authoring from Claude (tokens) and the wrapper
   confusion (point 2 above). Any pipeline that hands cards to an agent should print its own prompt this way.
   Code: `agent/concept_graph/prompts.py`, `cli.py` `_cmd_collect`, tests in `test_cg_prompts.py`.
2. **Use Antigravity for bulk drafting across the project** wherever API cost or Claude token use is high and a slow,
   human-relayed turnaround is acceptable. Candidates to assess one by one (not verified here): pipelines that today
   draft in bulk with metered Gemini or with Claude, such as the study-guide and summary-enhancement pipelines, problem
   generation, and the video-lecture-notes pipeline. The test for each: are the cards generated by code, and are the
   results validated by code?
3. **Keep Claude for design and for review of a sample,** not for bulk drafting: spot-check about 10% of agent critic
   verdicts against their passages and report the disagreement rate.
4. **Use the Codex subscription as the reviewer** for steps that do not need Claude's design judgement (critic
   spot-checks, whole-branch review of mechanical changes, test and Git work, as `docs/AGENT_ROUTING.md` already
   suggests), to spend no Claude tokens there. Pilot it on the same 10% sample and compare with Claude's verdicts
   before relying on it.
5. **Reserve the metered API for unattended or very large runs,** behind the existing cost gate and the over-$1
   warning, and keep the free-key and keyword fallbacks for retrieval.
6. **Improve the critic** (separate brainstorm): a different model than the drafter, a stricter rubric
   (direction and condition checks), seeded known-bad edges to measure leniency, or Claude/Codex review of a sample.

## Open question: removing the human relay

Removing the human step needs a connection between agents, for example an MCP server that exposes `collect`, the
worklist and `submit` as tools so an agent can pull its own run and hand it back, or a headless agent CLI invoked
by the pipeline. Neither is built. Trade-offs to examine in a brainstorm: authentication and subscription terms for
unattended use, who validates and who commits (the validators already live in `submit`), blast radius if an agent
writes to the graph repo, and whether a human checkpoint should remain before anything is published.

## Suggested order

1. Spot-check sample of critic verdicts (cheap; gives the leniency number).
2. Roll the printed-prompt idea into the other card-based pipelines as they are touched.
3. Pilot Codex as sample reviewer.
4. Brainstorm the critic and the human-relay options in a separate session.
