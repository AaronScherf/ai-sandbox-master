# Handoff: test JMMI API for Somalia and Sudan panel use

*Prepared 2026-11-09. This is a prompt for a separate, bounded data-access check; no API request or panel integration was run while preparing it.*

> Please test the [REACH JMMI API dashboard/documentation](https://impact-initiatives.shinyapps.io/JMMI-API-Dashboard/#) for possible use in the existing `compound-shocks-panel` Somalia and Sudan instances. REACH's [2025 global JMMI guidance](https://marketsincrises.net/wp-content/uploads/2025/08/REACH-Joint-Market-Monitoring-Initiative-JMMI-Guidance-Document-V1-2025.pdf), especially Annex 3, documents an open API with a 200-calls-per-IP monthly limit and explains market-price, minimum-expenditure-basket, and market-functionality variables. The dashboard URL itself did not load in a web reader during this handoff; verify it in the actual test environment and find its documented endpoint rather than guessing one.
>
> **Goal:** Determine whether the open API currently returns usable Somalia and Sudan data, and whether a **small sample** could be aligned to the panel's country-specific geography, month, commodity, and time range. This is a feasibility check, not authorization to ingest all rounds or change production panel outputs.
>
> **Workspace:** Read `AGENTS.md`, `docs/WORKTREE_WORKFLOW.md`, `docs/WORKTREE_DATA_AND_RETIRE.md`, `PROJECTS.md`, and relevant project guidance before writing. `projects/compound-shocks-panel` is a separate Git repository present only in the main checkout; inspect its `instances/somalia/config.yaml`, `instances/sudan/config.yaml`, source descriptors, and price transforms **read-only**. Use a dedicated task worktree for any report or code changes, and do not write into the shared live panel checkout or corpus.
>
> **Steps:** (1) Check dashboard/API availability, documented authentication, rate limit, terms, and a metadata or catalog request. (2) Identify country/round coverage for Somalia and Sudan; request the smallest useful sample of each and save only non-sensitive sample metadata or a permitted tiny extract in the task worktree. (3) Record field names, types, currency, price units, commodity labels, location IDs/names and coordinates if provided, collection dates, sample/market count, missingness, and whether data are vendor observations or aggregates. (4) Compare a few records against the panel's WFP price input and Admin-2/locality boundaries; document feasible join keys and ambiguous/unmatched places. (5) State whether the API is reachable, relevant data exist, data can be downloaded within terms, a join appears possible, and whether it measures a genuinely new construct (such as vendor restocking or functionality) rather than duplicating WFP prices. Distinguish each conclusion.
>
> **Deliverable:** A local Markdown feasibility report with exact request URLs/parameters **without credentials**, response status, retrieval date, small sample counts, schema and join examples, limitations, and a clear go/no-go/unknown conclusion for each country. Include proposed next work only if a real integration gap remains. Do not claim panel integration or run panel rebuilds unless separately requested.
