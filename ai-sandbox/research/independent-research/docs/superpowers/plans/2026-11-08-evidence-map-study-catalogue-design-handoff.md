## Design questions for Claude to settle with the owner

1. **Catalogue unit and identity.** Is a row a paper, a distinct evaluation, a program, or a replication deposit? Define stable IDs and links among versions, working papers, published articles, multi-arm programs, reviews, and datasets. Define how changed metadata or a new paper version invalidates a prior screening/classification decision without resurfacing every declined hit as new.
2. **Minimum machine-readable catalogue.** Select the source of truth, path, format (CSV, JSON, or another justified format), fields, provenance, controlled values, access/rights status, and versioned export contract. Keep discovery hits, screened works, and replication deposits distinct. Decide whether the catalogue is in the monorepo, child evidence repo, or ignored local store; map every write and sync process. The public projection must exclude quote-bearing and restricted content.
3. **Smallest first release.** Decide whether a curated seed catalogue of a few verified study records and replication links can be useful before automated multi-provider search. Specify acceptance evidence, including a varied read-only sample checked against provider records and false-positive logging. Avoid treating a passing fixture test as live catalogue validation.
4. **Two-pass screening.** Make comparison versus compound-conflict setting mutually understandable, define treatment-effect and context-only evidence types, exclusion reasons, and when a source enters the public manifest. Decide how contextual sources can be included without pretending they contain comparable effect estimates.
5. **Search after the catalogue.** Specify the first provider set and exact query/export logging contract, limits and deduplication, replication-deposit matching, and what requires manual review. Determine which existing OpenAlex code can be reused; treat Semantic Scholar candidate search and taxonomy discovery-loop expansion as prerequisites if required, not existing behavior. The search should consume or update the catalogue through a stable interface.
6. **Taxonomy handoff.** Define a rights-safe, versioned mapping from catalogue IDs to `agent/literature` IDs and 3ie-derived facets; distinguish unclassified, proposed, verified, and stale assignments. Decide how reviewed per-source tags reach a filterable public output without putting quotes or 3ie-owned term text into the public repo. Follow the interactive Artifact convention for owner decisions in `academic-rag-model/CLAUDE.md`.
7. **Operations and cost.** If any discovery or classification runs unattended, specify the actual execution mechanism, query/API scan cost, persistent cursor/state, retries, deduplication and reappearance rules, and behavior when no reviewer is available. Keep paid AI extraction behind `compute.yaml` and the >$1 owner gate.
